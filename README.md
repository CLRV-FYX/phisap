## 如何使用

### 准备
0. **请安装Python 3.11或更高版本（3.12/3.13等均可）**
    + 请使用正式版，不要使用开发者预览(early developer preview)版
        + 如果你非要用，请使用`3.11.0a5`及以后的版本，否则你可能会遇到一些问题，见issue#71
1. 使用`pip install --prefer-binary -r requirements.txt`安装依赖（依赖`av`会直接下载预编译包，无需本地编译）
    + Windows 下也可以直接双击`start.cmd`，自动安装依赖并启动
    + **更新**：双击`update.cmd`即可自动下载最新代码并替换旧文件（保留`Assets`谱面库和`cache`设置，旧文件备份在隐藏目录`.old_version`中）
2. 请安装`Android Debug Bridge`，**要求版本号至少为`1.0.41`**，并确保相应的环境变量已经配置好。
3. 准备谱面文件（JSON）。**phisap当前为"谱面导入"模式：不解析游戏安装包，只需提供谱面json**
    + 支持**各版本官方谱面**（`formatVersion` 1/2/3，覆盖Phigros 2.x至3.20.0+，如`Chart_SP.json`、`Chart_AT #4159.json`），原样保存
        + 3.20.0起的新版官谱（`formatVersion: 3`）已支持解析；带` #<id>`后缀的文件名会自动识别难度
    + 支持**RPE谱面**（RPE/PEConverter输出的JSON）
        + 导入时自动转换为等价的v3结构（时间/x/旋转/透明度/速度/类型/按住时长均与官方原谱逐点验证过），之后与官谱走完全相同的解析/规划流程
    + 导入方式（二选一）:
        + 点击程序左上角"导入谱面"按钮，选择一个或多个json文件，按提示输入曲目ID（谱面将保存为`./Assets/Tracks/<曲目ID>/Chart_<难度>.json`）
        + 直接把json文件放入`./Assets/Tracks/<曲目ID>/`目录（可点"打开谱面目录"按钮定位），文件名需含难度（如`Chart_AT.json`）
    + 谱面json请使用你自己的渠道获取（如PEConverter等工具导出）。phisap本身不附带、不传播任何版权谱面数据
4. 准备服务端。`scrcpy-server-v4.1` 已随本仓库提供（与`main.py`同目录），**无需单独下载**。
    + phisap的协议实现与scrcpy `v4.1`严格对应（server会校验版本号），请勿替换为其他版本
    + v4.1支持Android 5 ~ 16（旧版phisap使用的v2.0在Android 14/15上会崩溃，如MuMu模拟器的Android 15镜像）
    + 如果该文件缺失（比如你从别处复制了不完整的目录），可以用下面的命令补全:
        ```bash
        cd phisap  # 定位到phisap的根目录下
        wget https://github.com/Genymobile/scrcpy/releases/download/v4.1/scrcpy-server-v4.1
        ```
        Windows用户直接双击`start.cmd`，它会在文件缺失时自动下载

### 运行
**Windows**: 双击`start.cmd`（首次运行会自动安装依赖）

*nix/手动方式*:
```bash
cd phisap # 将CWD(Current Working Directory，当前工作目录)设置为phisap的根目录，以便phisap查找服务端文件
python main.py
```

**屏幕尺寸**: 连接设备后phisap会从scrcpy获取当前屏幕尺寸，**请先在设备上打开Phigros（横屏）再点"开始"**。phisap会将Phigros的`1280×720`逻辑画布按16:9居中适配(contain)到实际屏幕，非16:9屏幕（如`2400×1080`）自动留边。屏幕尺寸默认自动检测，如果检测不准，可以在程序界面的"屏幕尺寸"一栏选择常见预设（如`1920×1080`），也可以直接手动输入`宽×高`（如`1290×2712`），设置会被记住

## 工作原理
+ 读取谱面库（`./Assets/Tracks/<曲目ID>/`）中的谱面文件；RPE谱面在导入时已转换为v3格式
+ 解析谱面文件（官方v1/v2/v3），分析出每个音符的击打位置、击打方式和击打时间
+ 将这些击打操作转换为触控事件序列
    + 即按下(DOWN)、移动(MOVE)和抬起(UP)
+ 开始操作后，逐一向设备发送这些触控事件


## 注意事项
+ 虽然phisap的灵感来源为`sudo 板子自己打歌 `，不过**本程序并不依赖root权限工作**
+ 一些情况下有可能因误触发三指截屏或通知中心而导致miss，不是每台设备都会触发，视厂商和设备型号而定
+ **phisap当前完美支持的最高版本为3.1.0**，所有的曲目/任意难度均可以打出金φ，除了一些特殊类型的谱面（不用担心，不会影响rks）。这些谱面详见[暂不支持的谱面](#暂不支持的谱面)。3.20.0起的新版官谱格式(`formatVersion: 3`)已可正常解析和规划，3.20.0以上版本的AP表现如有异常请开issue反馈
+ 在使用phisap时如果某些谱面无法AP，那么这时你需要
    + 确保计时器同步的精确程度满足要求，如果你发现phisap打出了FULL COMBO，但并没有AP，这**一定**说明你的计时器同步没有做好
    + 如果计时器同步没有问题，那么你可以试试换一个规划算法。目前一些谱面只能由algo1达成AP，而另一些只能由algo2达成，当然，大部分的谱面使用algo1和algo2都可以完成（新增的algo3/algo3f用扫屏的方式处理drag/flick，建议优先尝试）
    + 如果你发现还是不行，那么你可以考虑开一个issue，跟我说明这个问题

PS: 如果你知道怎样实现不root的前提下精确获知当前曲目进度，且愿意帮助本项目的话，请开issue告知我做法

这些玩意太逆天了，不在phisap的全p目标范围内。phisap作者并不会针对愚人节谱面进行规划算法的改进

## 课题模式
phisap并没有对课题模式做特殊的支持，将来也许会有

不过现有的功能完全可以使你拿到彩48标签，但是需要一点点技巧

我推荐的配置是
+ 迷宫莉莉丝 (AT16)
+ 狂喜兰舞 (AT16)
+ DESTRUCTION 3,2,1 (AT16)

也就是下面这三个，顺序任意
![推荐彩48配置](./public/img/screenshots/phone-shot3.jpg)
这三个谱面的特点是开局没有过分的判定线演出，便于手动同步定时器，同时相比于其他AT16，这三个谱面在课题模式下也算是判定比较宽松的

然后按照如下步骤操作phisap
1. 使用algo1规划这三个谱面（注意难度选AT）
    + 计时器同步方式选手动同步，选定曲目ID和难度之后点开始，按钮变成“开始操作”后关掉phisap，再打开，重复这一步骤
        + 这个操作逻辑确实有点蠢，不过新UI正在设计了（
2. 同步方式选手动，曲目ID选择第一首的，难度选AT，规划算法选不规划，然后点开始
3. 在游戏设备上设置课题模式并开始
4. 看着游戏设备，在note快落到判定线时点击“开始操作”按钮或者按下空格键
5. 观察note被击打时相对判定线的位置，调整“微调”，确保note在击打时跟判定线重合
    + 如果你开局就蓝线了那也就甭微调了，直接重开罢
6. 在phisap自动游玩当前谱面时，调整曲目ID为下一首的曲目ID
7. 在phisap的按钮重新变回“开始”/看到控制台输出“操作结束”后，点击“开始”按钮。此时你的游戏设备应该还在加载下一首曲目
8. 为剩下两首曲目重复步骤4到7
9. 如果运气好的话，你应该能得到一个彩48

## 更新日志
### (2026/09/27) 滑键触点（flick不再重新按下）/ 发送时序排查
+ **flick只靠滑动判定，不再用重新按下的触点**（撤销上一版的"flick总是新按下"）
    + algo3/algo3f新增若干个**滑键触点**（16触点时4个，10触点时2~3个），专门处理flick：每一段flick（间隔小于1.5秒的连在一起）开始前在不会碰到tap/hold的位置按下一次，之后一直不抬起，依次滑到每个flick的位置快速划一下（100ms内划200像素，垂直于判定线），整段结束后才抬起
    + 相邻两划方向错开（和上一次移动方向的点积≤0），游戏会把它当成新的一划；几个滑键触点轮流接，成批的flick也能接住
    + 触点分配：algo3f = 2个扫屏 + 4个滑键 + 10个tap/hold（10触点时 2+3+5）；algo3 = 4个扫屏 + 4个滑键 + 8个tap/hold（10触点时 3+2+5）
    + algo1/algo2恢复为原来的复用触点方式
+ 判定模拟器新增`--phigros`：按Phigros的规则，每次按下只判定范围内最早的一个Tap/Hold，一次滑动只能判定一个flick，已经判定过的flick不会再被别的滑动"吃掉"（与sim-phi一致）。7张官谱×2次、60帧/30帧下algo3、algo3f的tap/hold/flick全部Perfect（algo3f 30帧时有8个drag漏判，与之前相同），10触点时同样全部Perfect
+ **发送时序**（排查tap/hold莫名断连）：
    + 同一毫秒的事件合并成一次发送；离下一批事件还早时短暂sleep，减少和界面线程抢占
    + 打歌期间冻结Python垃圾回收（完整回收几十万个事件对象可能卡顿几十毫秒）
    + 打歌结束后在控制台输出**发送统计**：最大延迟，以及晚于计划超过20ms的时刻（从第一个音符算起）。如果断连的时刻和这里列出的时刻对得上，说明是电脑/adb发送卡顿造成的
+ 规划缓存改为`.ans.v5.json`（需要重新规划）

### (2026/09/27) 成批出现的flick漏判修复
+ **原因：一次滑动只能判定一个flick**。按[sim-phi](https://github.com/lchzh3473/sim-phi)（Phigros网页模拟器）的判定规则，触点进入"甩动"状态后只能判定一个flick，必须先减速或反向才能判定下一个。扫屏触点每次单程（约0.1秒）最多只能接一个flick，扫得再快也接不住成批的flick；而且游戏每帧只读一次触点位置，扫得太快反而会跳过音符
+ **algo3/algo3f的flick改为单独规划**：每个flick由一个触点单独快速滑一下（扫屏触点碰巧接到的也算），扫屏触点只负责drag
+ **flick滑动加快、加长**（所有算法）：由"60ms内滑60像素（1像素/毫秒）"改为"100ms内滑200像素（2像素/毫秒）"。之前的速度刚好卡在甩动判定的门槛上，30帧时也来不及判定
    + 靠近屏幕边缘时整段滑动沿垂直于判定线的方向平移到屏幕内（之前会被截断在边缘上滑不动）
    + flick总是用新按下的触点（之前可能复用旁边的触点，先"瞬移"到起点，这一下会占用"一次滑动"）
+ 判定模拟器新增`--strict-flick`（一次滑动只能判定一个flick）。7张官谱、每种条件2次，非Perfect总数（修改前→修改后）：

| 算法 | 60帧 | 30帧 | 120帧 | 15.6ms时钟+10ms抖动 |
|---|---|---|---|---|
| algo1 | 267→6 | 728→7 | 46→7 | 446→24 |
| algo2 | 345→6 | 865→6 | 75→7 | 466→6 |
| algo3 | 0→0 | 4→0 | 0→0 | 0→0 |
| algo3f | 42→0 | 173→7 | 21→0 | 43→0 |

+ 规划缓存改为`.ans.v4.json`（需要重新规划）
### (2026/09/26) 新增algo3f（坐标轴扫屏）
+ **新增规划算法algo3f**，在"规划算法"中排在algo3之后
    + 像坐标系的两条轴一样：1个触点在屏幕高度正中（y=360）左右来回扫过整个宽度，1个触点在屏幕宽度正中（x=640）上下来回扫过整个高度
    + 从第一个音符之前1秒按下，一直扫到最后一个音符之后才抬起，drag（黄键）和flick（红键）完全不规划；其余触点（16触点时14个，10触点时8个）按algo2的方式处理tap和hold（2026/09/27起flick也改为单独规划，见上）
    + 横轴单程约103ms（约12000像素/秒），纵轴单程约71ms（约9600像素/秒）；两个触点合计每秒约330个事件
    + 判定模拟：8张官谱在45/60/90/120/144帧下全部Perfect；30帧时flick密集的段落会漏（例如996 IN平均每次约20个），因为只有两个扫屏触点，每个触点每帧最多判定一个flick。请把模拟器帧率设为60或更高
+ **修复algo3在"手动同步"模式下整体偏移的问题**：手动同步以"第一个事件"对齐按下按钮的时刻，而扫屏触点会在第一个音符之前就按下（例如谱面以drag开头时提前约0.44秒），导致整首歌的操作都提前。现在以第一个音符对齐（algo1/algo2的行为不变），第一个音符之前的扫屏事件在按下按钮时立即发送
+ 扫屏触点按下的位置避开左上角的暂停按钮
### (2026/09/26) 新增algo3（扫屏）/ 发送时序修复
+ **新增规划算法algo3（扫屏，推荐）**，在"规划算法"中排在第一个
    + 若干个专用触点（16触点时4个，10触点时3个）在有drag（黄键）/flick（红键）的时间段内不停地左右高速扫过整个屏幕（约12000像素/秒，60帧下每帧约210像素，小于判定宽度），drag和flick不再逐个规划
    + 每个扫屏触点负责一行（不同的高度），因为判定只看触点在判定线方向上的投影：竖直的判定线只靠左右扫动是扫不到的，按行分布后任意角度的判定线都能覆盖
    + 其余触点（12个/7个）按algo2的方式处理tap（蓝键）和hold
    + 扫屏触点只在drag/flick前后0.4秒内出现（间隔小于1.5秒的段合并），按下时会避开前后0.3秒内所有tap/hold的判定范围（按下的那一下会被游戏当成一次点击），并先静止40ms再开始扫动
    + 扫屏期间每个触点每6ms发送一次位置，4个触点合计约每秒670个事件
+ **发送计时改用`time.perf_counter()`**：Windows上Python 3.12的`time.time()`精度只有约15.6ms，触控事件会被攒成一批一批地发出（Python 3.13起才改为高精度）
+ **控制通道关闭Nagle算法（TCP_NODELAY）**：触控消息只有32字节，默认会被攒包/等待确认后才发出，可能让个别按下/抬起被延迟
+ **长按的MOVE事件精简**：长按跟随判定线时原本每毫秒发送一个MOVE（判定线静止时全是重复位置），现在位置不变时不发送、缓慢移动时最多4ms发送一次（误差不超过6像素）。同一谱面的触控事件数减少约85%（例如Spasmodic IN从6.2万降到8千），减轻scrcpy/模拟器的注入压力
+ 新增判定模拟器`tools/judge_sim.py`：按Phira（复刻Phigros判定）的判定逻辑回放规划结果，统计每种音符的Perfect/Good/Bad/Miss，可模拟不同帧率、判定宽度、发送时钟精度和延迟抖动
    + 用法：`python tools/judge_sim.py <谱面.json> [algo1 algo2 algo3]`
    + 在8张官谱（Rrhar'il、Igallta、DESTRUCTION 3,2,1、Spasmodic、Luminescence、Aleph-0、996等）上，60帧/30帧/120帧、判定宽度缩小到100像素、15.6ms时钟+10ms抖动、40ms抖动这几种条件下，algo3全部Perfect；algo1/algo2在同样条件下分别有6~40/2~7个非Perfect（主要是flick）
    + 注意：模拟器只能验证"规划本身"是否正确，真机上的延迟、掉帧、模拟器的注入能力等因素无法模拟

### (2026/09/26) 旋转判定线漏判修复 / 解除触点上限
+ **修复官谱与RPE谱面的判定线上下镜像**（旋转判定线上漏判的主要原因）
    + 官谱`formatVersion 3`（包括3.20.0起的新官谱）判定线移动事件的y分量一直是**0在底部、向上为正**（见[谱面格式说明](https://docs.lchzh.net/learning/phigros/)与Phira的解析代码），之前误当成"0在顶部"解析，判定线的上下位置被镜像
    + Phigros按触点在判定线方向上的投影判定，线水平时上下镜像不影响判定，所以大部分音符能打中；一旦判定线旋转，偏差就会投影到判定线方向上导致漏判
+ **RPE谱面转换按Phira的规则重写**（导入过的RPE谱面请重新导入）
    + 支持缓动（easingType 1~29、easingLeft/easingRight截取、贝塞尔曲线），之前所有事件都被当成线性，缓动旋转/移动的位置全部算错
    + 支持多个事件层相加（之前只用第1层）、父子线（father / rotateWithFather）、BPM变化（之前每条线只取一个bpm，变速后的音符时间全部偏移）
    + RPE的offset单位为毫秒（之前按秒保存）
+ **长按与滑键跟随判定线**
    + algo2：长按由同一个触点逐毫秒跟随判定线移动/旋转直到结束（之前触点停在按下的位置，判定线一转就断）
    + algo1/algo2：滑键的滑动轨迹逐毫秒跟随判定线（之前固定在判定时刻的位置），滑动超出屏幕时限制在屏幕内
    + algo1：长按在屏幕外判定时使用当时的判定线角度映射回屏幕
+ **同时触点上限由10提高到16**（Android系统的硬上限）
    + 官方scrcpy-server最多只允许10个触点，第11个触点会被静默丢弃。phisap启动时自动生成补丁版`scrcpy-server-v4.1-16pt`（只修改服务端中与触点上限相关的4条指令并重新计算校验和，校验不符时自动退回官方原版与10触点）
    + 规划算法不再因超过触点上限而报错退出：algo1会提前抬起闲置的触点，algo2在触点不足时跳过并给出警告
+ 规划缓存改为`.ans.v2.json`，旧版本生成的`.ans.json`（基于错误的坐标）会被自动忽略，请重新规划
+ 新增测试：`tests/test_rpe_motion.py`（缓动/事件层/父线/BPM）、`tests/test_algo.py`（旋转判定线上的长按/滑键跟随、触点上限、随机谱面的事件序列合法性）、`tests/test_server_patch.py`
